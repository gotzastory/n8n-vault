# Pattern - AI Agent with Tools

## Problem
งานที่ไม่รู้ล่วงหน้าว่าต้องทำขั้นตอนไหนบ้าง — ต้องให้ LLM ตัดสินใจเองว่าจะเรียกเครื่องมือไหน เมื่อไหร่

## Workflow Shape
```
Trigger (Chat Trigger / [[Node - Webhook]] / [[Node - Schedule Trigger]])
    ↓
[[Node - AI Agent]]
    ├─ Chat Model        ← [[Node - Chat Model]] (บังคับ)
    ├─ Memory            ← Window Buffer / Postgres Chat Memory (1 ตัวเท่านั้น)
    └─ Tools             ← [[Node - Tool (AI)]] (บังคับอย่างน้อย 1)
    ↓
output (`{{ $json.output }}`)
```

## เลือก tool ยังไง
| ต้องการ | ใช้ |
|---|---|
| ให้ agent เรียก workflow อื่น | **Call n8n Workflow Tool** |
| ยิง API ตรงๆ | **HTTP Request Tool** |
| ค้นความรู้ภายใน | Vector Store Tool → [[Node - Vector Store]] |
| ใช้ app node ที่มีอยู่ (Gmail/Slack/Sheets) | node-as-tool + `$fromAI()` |
| แบ่งงานให้ agent เฉพาะทาง | **AI Agent Tool** (multi-agent, n8n 1.103.0+) |

## `$fromAI()` — ให้ LLM เติมค่า parameter
```javascript
{{ $fromAI("url", "a valid url of an image", "string", " ") }}
{{ "Generated by AI: " + $fromAI("subject") }}
```
ใช้ได้เฉพาะ tool ที่ต่อกับ AI Agent — ดู [[Node - Tool (AI)]]

## Design decision: chain vs agent delegation
| | Prompt chaining | Agent delegation |
|---|---|---|
| ลำดับ | กำหนดตายตัวตอน design | เกิดตอน runtime |
| ใช้เมื่อ | step รู้ล่วงหน้า, predictable, ประหยัด token | step ขึ้นกับ input, ต้อง reasoning |

**ระบบที่ดีผสมทั้งสอง**: ใช้ chain ([[Node - Basic LLM Chain]]) กับส่วนที่แน่นอน (extract, format, validate) และ agent เฉพาะส่วนที่ต้องคิดจริงๆ — ลดขอบเขต reasoning ให้แคบที่สุด

ตัวอย่าง hybrid:
1. Basic LLM Chain สกัดข้อมูลเป็น structured (fixed)
2. **AI Agent** เลือกว่าจะ query billing API / knowledge base / CRM (flexible)
3. Basic LLM Chain ร่างคำตอบตาม template (fixed)
4. [[Node - Code]] validate + route ตาม confidence (deterministic)

## ทำให้ agent เชื่อถือได้
- **System Message** ชัดเจน: บทบาท, น้ำเสียง, ห้ามทำอะไร, ควรใช้ tool ไหนเมื่อไหร่
- ใส่ context จริงเข้า prompt ด้วย expression (`{{ $json.customerName }}`, `{{ $now.toISO() }}`)
- **Structured Output Parser** บังคับ JSON schema → ค่าคงที่ทุกครั้ง (`"billing"` ไม่ใช่ `"BILLING"`/`"Payment"`)
- เปิด **Enable Fallback Model** เผื่อ model หลักล่ม
- ตั้ง **Max Iterations** กันวนไม่จบ
- **Human-in-the-loop**: ต่อ [[Node - Slack]] / [[Node - Gmail]] เป็น review step ก่อน tool ที่อันตราย

## Gotchas
- **Description ของ tool คือทุกอย่าง** — LLM ใช้ตัดสินใจ. คลุมเครือ = เรียกมั่ว
- tool เยอะเกินทำให้สับสน + กิน token → รวมหลาย API เป็น sub-workflow tool เดียว
- agent หลักไม่ส่ง execution context เต็มให้ AI Agent Tool — ต้องใส่ใน prompt เอง
- agent รันหลายรอบต่อ 1 execution (setup → tool → ประเมิน → ตอบ)
- Queue mode: sub-workflow tool รันบน worker เดียวกับ parent
