# Node - Tool (AI)

## What it does
Tool = "ฟังก์ชัน" ที่ LLM เรียกใช้เองได้เพื่อเข้าถึงข้อมูล/ทำ action นอกตัวมันเอง. ต่อเป็น sub-node เข้ากับ [[Node - AI Agent]] (**ต้องมีอย่างน้อย 1 ตัว**)

## Tool ที่ทรงพลังที่สุด 3 ตัว
| Tool | ใช้ทำอะไร |
|---|---|
| **Call n8n Workflow Tool** | โหลด workflow ใดก็ได้มาเป็น tool — ห่อ API call หลายตัวไว้ใน sub-workflow เดียว ลดจำนวน tool ที่ agent ต้องจัดการ + คุมลำดับการเรียกได้ + ประหยัด token |
| **Custom Code Tool** | เขียน code ให้ agent รัน |
| **HTTP Request Tool** | ยิง API / ดึงเว็บ — ดู [[Node - HTTP Request]] |

อื่นๆ: Wikipedia, SerpAPI, Calculator, Vector Store Tool ([[Node - Vector Store]]), MCP Client Tool, AI Agent Tool (multi-agent)

## Node-as-tool
node n8n ยอดนิยม ~20 ตัว (Gmail, Slack, Google Sheets ฯลฯ) ต่อเป็น tool ได้ตรงๆ — ต่างจาก action node ปกติตรงที่:
- ต่อเข้า root AI node เท่านั้น ไม่ต่อกันเองในสาย
- parameter เติมค่าตอน runtime โดย LLM ผ่าน `$fromAI()`

## `$fromAI()` — ให้ LLM เติมค่า parameter เอง
```javascript
$fromAI(key, description?, type?, defaultValue?)

{{ $fromAI("url", "a valid url of an image", "string", " ") }}
{{ $fromAI("email") }}
{{ "Generated by AI: " + $fromAI("subject") }}   // ผสมกับ text คงที่ได้
```
| Parameter | บังคับ | หมายเหตุ |
|---|---|---|
| `key` | ✅ | 1-64 ตัวอักษร, a-z A-Z 0-9 `_` `-` เท่านั้น |
| `description` | ❌ | บอก context ให้ model ตอบตรงขึ้น |
| `type` | ❌ | string (default) / number / boolean / json |
| `defaultValue` | ❌ | ใช้เมื่อ model ไม่คืนค่า |

**สำคัญ**: `key` ไม่ใช่ reference ไปหาค่าที่มีอยู่ — เป็น **hint** ให้ model หาค่ามาเติมจาก context/tool อื่น/ถามผู้ใช้

**`$fromAI()` ใช้ได้เฉพาะ tool ที่ต่อกับ AI Agent** — ใช้กับ Code tool หรือ sub-node ที่ไม่ใช่ tool ไม่ได้

## Human-in-the-loop
ต่อ human review step ก่อน tool ทำงานจริงได้ — ใช้ตัวแปร `$tool`:
- `$tool.name` — ชื่อ node ที่ agent จะเรียก
- `$tool.parameters` — ค่าที่ agent จะใช้ (รวมค่าที่มาจาก `$fromAI()`)

## Parallel vs sequential
Agent ตัดสินใจเองว่าจะเรียก tool พร้อมกัน (งานอิสระต่อกัน เช่นแปลง 2 สกุลเงิน) หรือเรียงลำดับ (งานที่ต้องใช้ผลก่อนหน้า) — ไม่ต้องเขียน code คุมเอง

## Gotcha
- **Description คือทุกอย่าง** — LLM ใช้ description ตัดสินใจว่าจะเรียก tool ไหน เขียนคลุมเครือ = agent เรียกมั่ว
- Sub-node resolve expression เป็น item แรกเสมอ
- tool เยอะเกินไปทำให้ agent สับสน + กิน token — รวมเป็น sub-workflow tool เดียวดีกว่า
